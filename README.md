# swift-shader-compiler

Use this package to turn kernels written with swift-shader into a GPU's language, from the WebAssembly module Swift compiles them to. Start from `Shader.Compiler.metal(_:)` for Metal's shading language, `Shader.Compiler.wgsl(_:)` for WGSL, the browser's, and `Shader.Compiler.File` for the generated Swift file that carries the text. It does not run the Swift compiler: the `institute shader` command does, and hands the module here.

## Laws

- The text is the module's operations in Metal's normal maths: division and square root are the GPU's own, and the compiler may fuse a multiply and an add, so a result may differ from the module's in its last bits; constants are written as bit patterns, and integer operations give the same bits. Where a GPU flushes a subnormal `float`, results may differ there too.
- What cannot be written exactly is refused with an error that names it: `Double`, recursion, a call through a pointer, a growing memory, an import that is not the shader's, a buffer whose number is not known when the code is compiled. Nothing is guessed or left out.
- Imported `__extendhfsf2` and `__truncsfhf2` are the conversions between `Float16` and `Float`, rounded to nearest even.
- A trap ends its function, whose result is then 0.
- The module's own memory is its stack, whose size is the deepest path of calls, and its data, which is read only: a store outside the stack does nothing. Swift's module hashes (data named `.swift_modhash`, which change with the paths of a build) are left out of the data when the module's name section names them, so the same source gives the same text from any checkout.
- An export named `kernel_<name>` becomes a kernel of that name; its buffers are those its code reads or writes, read only where it only reads. An export named `function_<name>` becomes an inline function of that name; it gives its result, or the vector it handed to `Shader.result(_:)`.
- An export named `vertex_<name>` becomes a vertex stage and one named `fragment_<name>` a fragment stage, each under its exported name. A vertex stage takes the corner's and the instance's number and must give a position; a fragment stage takes the pixel's middle and must give all four components of a colour. What one hands the other is a vector at a numbered place, of `float`, or of whole numbers that are not interpolated. A stage reads buffers and textures and writes neither: one that does is refused by name.
- A texture is bound at a number of its own, apart from the buffers' numbers. It is read at a place, sampled at a point in its own measure (texels, a texel's middle at half), or, in a kernel, written at a place; an entry does not both read and write one. In Metal's language texture 0 is the surface a kernel writes, so the texture bound at number n is `[[texture(n + 1)]]`, and the sampler is `[[sampler(0)]]`. In WGSL the texture at number n is `shader_texture<n>` in group 1 at binding n, up to 8, a written one of `rgba16float`, and the sampler is `shader_sampler` in group 0 at binding 4.
- In WGSL each kernel is a module of its own, with only the functions it reaches. It has no pointers: the buffers an entry is handed are places in one array of words, `heap` (group 0, binding 0; read only in a stage), and a structure at binding 1 gives the grid's columns and rows and the place of each buffer by its number, up to 32. The module's data is a buffer at binding 2, read only, and the texture `present` writes, of `rgba8unorm`, is at binding 3. A workgroup is 64 places of one row, and places outside the grid do nothing.
- In WGSL a 64-bit integer is two 32-bit words, low first, and its operations are written out on them; dividing one is refused. A kernel's lanes are one, so a sum over them is the number itself, and a kernel that tells its lanes apart does each row's work in the row's first place alone. A kernel that stores single bytes in a buffer reads and writes `heap` atomically, so places beside each other keep each other's bytes. An operation on constants alone is worked out before the text is written, or read at run time where WGSL would refuse it when the text is compiled.
- Every other name in the text begins with `shader_` or `Shader_`, but a kernel's entry point in WGSL, which is the kernel's name.
- Equal modules give equal text.
- A generated file's first line says what it was made from, so that it can be made again from the file alone.
